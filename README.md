# 链接播放器 PWA

面向 iPad Safari 的原生 HLS / MP4 链接播放器，无构建步骤，发布于 GitHub Pages。

## 使用

1. 打开网站，在“导入视频”中确认预填链接，也可以粘贴其他 HTTPS 视频链接。
2. 点击“导入视频”。若 Safari 未自动开始，请点击播放器自带的播放按钮。
3. 播放进度约每 5 秒保存一次，也会在暂停、切换视频及页面隐藏时保存。
4. 再次打开网站，在播放记录中点击“继续播放”，媒体元数据加载后恢复位置。
5. 链接失效时点击“替换链接”。百度同一视频更换签名时会更新已有记录，保留进度。

支持从头播放、看完后重新播放、删除记录。默认链接是用户提供的临时百度播放地址，不保证长期有效，也不自动更新签名。

## 范围与限制

- 使用 Safari 原生 `<video>`，不设置 `crossorigin`，不在前端 `fetch` 解析第三方 HLS 清单。
- 实际能否播放取决于源站有效期、登录要求、外站访问限制及浏览器编解码支持。
- 不支持把普通网盘分享页自动解析为视频；不代理请求、不下载视频、不提供视频离线观看。
- 页面外壳可离线打开，视频仍需联网。记录保存在当前设备的 localStorage，最多 50 条，不会同步到 GitHub。
- 原备忘录数据未删除，保留在旧的 localStorage 键中。
- 默认播放链接随静态源码发布；其他用户输入的链接和记录仅保存在各自设备上。

## 部署与缓存

GitHub Pages 使用 `main` 分支及 `/ (root)`，通过 HTTPS 访问。
`sw.js` 预缓存根页面、HTML、JavaScript、样式、清单和图标；网络优先，失败时回退本应用缓存。
根地址和 `index.html` 共用页面更新；不会拦截第三方视频请求。
发布时递增 Service Worker 缓存版本，本版为 v5，页面版本 v3.2。

页面通过头部 `meta name="referrer" content="no-referrer"` 不发送来源地址。
2026-10-17 对默认链接的请求对比显示：携带本站 Referer 返回 403（31326），不携带时返回 HLS 清单，首个分片范围请求返回 206 和 TS 数据。此检查不等同于完整视频播放或 iPad 真机验收。

## 验证

Node.js 18+：

```sh
node --test tests/*.test.cjs
```

测试包含存储校验、签名链接更新、导入与播放事件、暂停保存、重开续播、替换链接、错误提示及缓存回退。
测试使用模拟媒体事件，不代替 iPad 真机验证。真机验收：播放到 20 秒左右，暂停并关闭，重开后继续播放，确认时间恢复。

播放失败时可展开“播放诊断”，查看原生 HLS 支持及浏览器媒体错误代码；“在新标签页直接打开视频”使用 noreferrer，可辅助区分嵌入播放与源站访问问题。诊断文本不包含签名视频 URL。
