## 已取得的数据

通过用户提供的分享链接和提取码，使用分享页本身的提取码验证、目录查询接口读取数据。没有读取或迁移浏览器登录 Cookie。

- 实际取得 240 个 MP4 文件，归类后每周恰好 5 个。
- 保留原始文件名、文件标识、路径、字节大小及源内容指纹。
- 目录结构完成不等于完整播放清单已取得：目前归档完整清单 2 份，另 238 份缺失。
- “完整目录”仅指此次分享接口可见的全部目录项，不包括源站隐藏或过滤的内容。

## 层级与编号

```text
assets/video/
├── catalog.json                         # 课程目录入口
├── default.m3u8                         # 现有默认来源，保持不变
└── english/
    └── s1/
        ├── catalog.json                 # 240 条视频记录
        ├── source-index.json            # 去除临时签名的源目录快照
        └── w1/
            ├── s1-w1-1.m3u8            # 08:57 / 54 分片
            └── s1-w1-2.m3u8            # 09:21 / 57 分片
```

全局 ID 为 `english-s1-w1-1`，展示名称为 `s1-w1-1`，课程标签为 `english`，阶段为 `s1`。其他清单的目标路径遵循 `w{周}/s1-w{周}-{课次}.m3u8`，尚未取得时不创建空文件或假清单。

`assets/video/catalog.json` 中的课程目录路径相对此文件解析；S1 目录中的 `expectedPlaylist` 和 `playlist.path` 相对于 S1 的 `catalog.json` 解析。不能相对于当前浏览器页面随意拼接。

视频记录包含：`id`、`name`、`courseId`、`subject`、`stage`、`week`、`order`、`source`、`expectedPlaylist`、`playlistStatus`、`playlist`。其中：

- `source` 保存文件标识、原始文件名/路径、大小以及可返回网盘定位的视频页面 URL。
- `playlist: null` 表示未取得完整清单，播放器不得把 `expectedPlaylist` 当作现成文件请求。
- `playlistStatus: missing-full-manifest` 表示等待取得完整清单。
- 已归档清单包含时长、分片数、SHA-256、版本、来源和分开的验证状态。
- `saved-needs-playback-validation` 表示本地有清单，不能据此认为分片尚未过期或已经通过 iPad 播放验收。
- 学习进度不写入共享目录；接入业务时应按固定视频 ID 关联现有本机记录及奖励逻辑。当前播放器尚未读取这份批量目录。

## 已有清单与本次探测

最初的 `w1/s1-w1-1.m3u8` 复制自项目原有 `assets/video/default.m3u8`。所有分片 URL 的内容指纹与源目录第一周 `1.mp4` 的指纹相符，文件标识为 `20690952231959`。清单为 537 秒、54 个分片，带 ENDLIST；此项只证明来源映射及清单结构，未重新验证全部分片或 iPad 解码。

本次用分享页正常的播放参数接口取得签名后，请求同一视频的 480p 媒体清单，响应只有 100 秒、10 个分片，即使带 ENDLIST 也不等于完整原片。该试看清单没有加入项目，未批量复制此类响应。需要恢复能取得完整视频的正常播放会话，再收集其余清单。不得通过修改时长、复制分片、变造签名或提高权限参数来补全。

分享提取码会话、临时签名参数和完整原始接口响应仅用于本次临时采集，未写入课程目录。源目录快照只保存整理所需字段，不含临时缩略图签名。已归档 M3U8 本身含原有临时媒体签名，沿用原测试清单公开范围；此次没有新增公开部署。

## 验证与维护

运行 `node scripts/build-english-s1-catalog.cjs`，可从去除临时签名的源目录快照重新生成目录。该脚本离线运行，不登录、不抓取、不下载视频。

本次验证：48 周，每周 1–5 五个编号，240 个唯一视频 ID，240 个唯一源文件标识，51 个目录全部成功响应且每个列表少于单页上限。当前两份清单均通过解析与源指纹校验；第一课已更新为最新附件，第二课为新附件。其余 238 项为 `null`，没有虚构清单、时长或播放成功状态。

后续导入新清单时先确认视频归属、完整时长和分片可用性，再按目标路径保存并重建目录。若源站改为新的指纹结构，需要人工核实后调整校验，不能略过来源校验。清单更新时应同步 revision 和真机验证状态；不要覆盖已关联的视频 ID。

保存清单不等于下载视频，当前没有离线视频缓存。

## v3.5 两项点播（2026-10-17）

定制页原“或导入 M3U8 清单文件”区域改为两个直接可点选的 item，保留普通链接导入和默认清单按钮。

| 课程项 | 附件清单 | 时长 | 分片 | 归档版本 |
| --- | --- | --- | --- | --- |
| s1-w1-1 | 前一条用户提供的个人网盘媒体清单 | 08:57 | 54 | 2 |
| s1-w1-2 | 本次用户提供的个人网盘媒体清单 | 09:21 | 57 | 1 |

- 配置集中在 `video-items.js`，包含固定课程 ID、显示名称、相对路径、预期时长和分片数。DOM 使用真实按钮，活动项与加载状态通过 ARIA 和样式展示。
- `hls-import.js` 读取所选清单，校验结构、时长与分片数，沿用独立 Cache Storage 和 SW 的 `__local_hls__/` 路由。清单没有自动加入应用预缓存；视频分片不缓存。
- `app.js` 复用历史记录、播放、保存与续播。选择课程项先退出“替换链接”模式，防止误覆盖另一视频。两份正文的哈希不同，因此播放记录独立；同一份清单再次选择不新增记录。
- 异步读取有请求序号保护：快速点第一课再点第二课，迟到的第一课结果或错误不会覆盖第二课。首次读取需异步准备；Safari 如阻止自动播放，保留原生播放按钮和明确提示。当前页面内再次点播已准备的清单直接复用缓存地址。
- 更新清单正文会改变播放器记录身份；目前固定课程 ID 仅用于配置，未迁移旧默认视频或旧签名记录的进度。旧记录保留，可通过原“替换链接”功能续用；后续批量目录接入时再统一固定 ID 的迁移。
- 未改首页和内容中心的占位入口，未将点播点击视为学习完成，未改奖励规则。
- `assets/video/default.m3u8` 仍为此前默认文件。用户随后明确要求部署本版本；此次发布包含这两份课程清单及其临时分片地址。
