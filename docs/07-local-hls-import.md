# 完整视频清单与一键导入（v3.4）

更新：2026-10-17。[返回文档索引](README.md)

## 当前采用的方案

使用用户提供的第二份完整 HLS 媒体清单：**537 秒（08:57）、54 个分片、带 EXT-X-ENDLIST**。不再将原 `/share/streaming` 接口作为默认来源；那个接口在无登录请求下只返回 100 秒。两份完整清单是同一视频的不同签名响应，不能拼接成更长视频。

无需后端、百度 Cookie 或登录凭证迁移。页面使用原生 `<video>` 播放清单引用的百度 CDN 分片。视频仍需联网，分片签名可能过期。

### iPad 一键测试

1. 打开 `https://yiersisan.github.io/pwatest/report.html`。如果显示更新提示，点击“保存进度并更新”；页脚应为 **v3.4 · 默认完整清单**。
2. 表单已经选中默认完整清单，直接点击“导入视频”，无需从“文件”App 选择清单。
3. 首次访问若提示本机清单未就绪，等离线界面准备完成后刷新再点击；Safari 若限制自动播放，点击视频的播放按钮。
4. 检查媒体实际时长，再拖到第 5 分钟确认画面和声音。清单显示 08:57 不等于视频已经解码成功。
5. 播放后暂停、重开页面，从记录点击“继续播放”，验证断点续播。

### 默认清单文件与配置

- `assets/video/default.m3u8`：第二份附件整理出的完整媒体清单，保留原始分片地址。
- `default-video.js`：默认地址、名称、预期时长和分片数量。地址相对当前页面解析，兼容 GitHub Pages 的 `/pwatest/` 子路径。
- `app.js`：预填默认来源；普通链接播放、历史记录及断点续播继续使用既有逻辑。
- `hls-import.js`：识别默认地址，联网读取清单，并验证其时长与分片数，再复用本机清单导入流程。不会静默退回 100 秒接口。
- `report.html`：默认完整清单提示、导入按钮、手动选择清单和可见的导入状态。

**公开测试范围：**用户于 2026-10-17 明确允许将第二份清单公开部署，用于 iPad 测试。因此该默认清单及临时签名可从公开网站/仓库读取，旧版本也可能留在 Git 历史中。此授权只用于这份测试清单；其他用户手动选择的清单仍只保存到当前浏览器，不上传服务器。

默认清单不加入 SW 应用资源预缓存；点击导入时请求最新清单。它的本机副本存入独立清单缓存。刷新默认清单需要替换文件、同步 `default-video.js` 元信息并更新 SW 版本；不能用旧签名推算或补造缺失分片。

## 本机导入流程

1. 默认来源直接读取部署的清单；手动导入最多选择 20 份文件、总计 4 MB、每份不超过 1 MB，并选择其中一份媒体清单。
2. `hls-core.js` 校验 `#EXTM3U`、EXTINF 与分片配对、有限正时长和 ENDLIST。拒绝错误 JSON、未结束的动态清单、变量清单；清晰度目录只标识，不能直接作为媒体清单导入。
3. 规范化分片及 KEY/MAP 的 URI 属性为 HTTPS 绝对地址，保留字节范围、加密和时间线标记。手动导入相对地址时，必须填写清单原始请求地址。
4. 以规范化正文的 SHA-256 生成 `__local_hls__/<hash>/playlist.m3u8` 地址，写入 `pwatest-imports-<scope>-v1` Cache Storage。
5. 检查活动 SW 支持此路由，读取回来的正文必须与保存内容一致，再发出 `pwatest:import-source` 事件导入播放记录。
6. SW 返回 HLS 内容类型及长度，支持单个起始字节范围请求；播放仍交给原生 `<video>`，分片直接请求源站。

SW 更新不删除用户清单缓存；删除播放记录会尝试删除对应清单。相同正文得到相同 URL，避免重复记录。从“替换链接”进入后选新清单可以保留进度和课程绑定；用更长清单替换短片时，清除旧“已完成”标记。不会伪造 `video.duration`。

首页/内容中心的占位播放入口共用新的默认完整清单地址，由现有 `watch-player.js` 直接交给原生播放器；其演示记录继续与真实课程记录隔离。占位入口不等同于定制页的本机导入操作。

## 不再采用的尝试

- 删除源码中的旧 100 秒默认 streaming 长链接；不把短清单当成完整片。
- 不复制 localStorage/Cookie、不嵌入扫码登录、不把跳转百度登录当成完整播放的保证。
- 不拼接多个清晰度或重复请求，不使用 Blob 清单试验页面。
- 不引入 HLS.js 或视频代理：本次分片抽样未返回跨域读取许可，不能假设浏览器 fetch 可以读取；项目仍是静态站点。

保留普通 HTTPS 直链导入、诊断及手动清单导入，这些是有效的现有功能。测试期间产生的探测页面和标准测试清单未放入部署文件；已存在的用户播放记录不自动删除。

## 验证证据与边界

- 两份附件解析结果均为 08:57、54 个分片。第一份的第 1、31、54 个分片小范围请求返回 206，样本具备 MPEG-TS 同步字节；这不是全部视频解码验收。
- 内置桌面浏览器对本机清单报过 `DEMUXER_ERROR_COULD_NOT_PARSE`；同一浏览器原始标准 HLS 可播放、本机清单失败。不能据此判定 Safari 不支持。
- 在说明 Mac Safari 导入步骤后，用户反馈“目前看着没什么问题”。记为用户当前环境的正向反馈；未据此将 iPad、逐个分片或断点续播标为全部验收通过。
- `node --test tests/*.test.cjs`：66 项通过。自动化测试覆盖完整默认清单校验、一键导入缓存路径、错误/短清单拒绝、未就绪 SW 提示、普通链接兼容、记录替换和 SW 范围响应。模拟测试不验证真实视频解码。

待 iPad Safari 与主屏幕 PWA 分别确认：实际时长、第五分钟画面和声音、结尾播放、暂停重开续播、清单过期后的替换、首次安装/更新，以及清除站点数据后的重新导入。不同浏览器与主屏幕实例不能假定共享记录或缓存。

保存清单不等于保存视频。断网时首页可以打开，但本方案没有实现离线视频下载。
