## 发布步骤

1. 完成本地修改，更新相关实现文档及[索引](README.md)。
2. 若修改应用代码或资源，递增 `sw.js` 的缓存版本；需要展示新页面版本时，同步更新 `index.html` 页脚和 `app.js` 的诊断版本，以及根 README 中的版本说明。仅文档更新不需要改应用版本。
3. 修改运行代码时执行下方测试。检查上传内容包含页面、脚本、样式、Manifest、图标、`.nojekyll` 和需要保留的文档/测试；不上传临时探测文件或本机依赖目录。
4. 将变更提交到 GitHub 的 `main` 分支。可使用已有 Git 工作流，或在仓库网页上传变更文件；先确认本地是否已经初始化 Git，不能假设当前目录可直接 `git push`。
5. 等待仓库 Actions 中 Pages 部署成功。提交成功不等于网站已完成发布。
6. 访问网站，重新加载后核对页脚和播放诊断版本，再验证本次变更涉及的功能。

此前自动化上传使用 GitHub 连接器的 Git Data API：读取当前分支头及其 tree，创建变更文件的 blob，在原 tree 上创建新 tree，创建以当前头为父节点的 commit，最后用 `expected_sha` 更新 `main`。这样保留未修改文件，并避免覆盖期间出现的新提交；若分支头已变化，应重新读取和合并，不强制覆盖。

## 自动化验证

在项目根目录使用 Node.js 18+ 执行：

```sh
node --test tests/*.test.cjs
```

| 测试文件 | 主要覆盖范围 |
| --- | --- |
| [hls-import.test.cjs](../tests/hls-import.test.cjs) | 默认完整清单校验、一键导入、本机缓存、短清单拒绝及未就绪提示 |
| [player.test.cjs](../tests/player.test.cjs) | URL 校验、签名链接去重、存储清洗、导入、替换、续播、切换、完成、异常提示及诊断 URL 脱敏 |
| [sw.test.cjs](../tests/sw.test.cjs) | 离线入口、网络更新、HTTP 错误回退、缓存清理隔离、存储写入失败、请求拦截边界及图标尺寸 |

播放器测试使用模拟 DOM 和媒体事件；Service Worker 测试使用模拟网络和缓存。它们不验证真实视频解码、网盘权限或 iPad 自动播放策略。

## iPad 真机验收

1. 在 Safari 打开网站，核对页面和脚本版本。
2. 在 report.html 点击“导入视频”，默认导入 08:57 完整清单；确认出现画面、声音和时长，不以“导入成功”替代播放成功。
3. 播放约 20 秒后暂停，关闭并重新打开，点击记录中的“继续播放”，检查恢复位置。
4. 替换同一视频链接，检查只有一条记录且进度保留；确认“从头播放”和“删除记录”有效。
5. 页面显示离线准备完成后断网重新打开，检查界面可用。视频未做离线下载，不能把此项当作离线视频验收。
6. 添加到主屏幕，检查入口图标和独立窗口；分别确认 Safari 与主屏幕实例里的实际记录行为，不假设不同入口必然共享状态。

## 部署问题定位

- 404：检查仓库名、访问路径、`main` 根目录是否存在 `index.html`、Pages 发布源以及部署任务是否成功。
- 页面版本旧：先核对远端提交和部署结果，再重新加载；同时查看页脚和诊断中的脚本版本，排查 HTML/JS 是否来自不同版本。
- 页面正常而视频失败：转到[播放问题排查记录](04-history-and-troubleshooting.md)，不能仅据视频错误判断 Pages 部署失败。
