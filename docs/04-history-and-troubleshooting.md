# 视频播放排查与方案结论

更新：2026-10-17。[返回文档索引](README.md)

当前实现以[完整视频清单与一键导入](07-local-hls-import.md)为准。本文件保留定位问题所需的结论，不再提供已经放弃的登录迁移、短链接或 Blob 清单试验步骤。

## 100 秒的原因与处理

原默认百度 streaming 接口在无 Cookie 探测中返回 10 个分片、合计 100 秒、带 ENDLIST。播放器只知道这些内容，改进度条或声明更长时长不能补出后续视频。用户在登录页面取得的两份清单均有 54 个分片、537 秒，因此改为使用完整清单，旧接口已从默认配置移除。

旧接口曾因携带本站 Referer 返回 403/31326，不带 Referer 时返回 HLS 清单。页面仍保留 `no-referrer`，但不能将这一次对照推广为所有错误的唯一原因。

## 保留的诊断

| 信号 | 含义 |
| --- | --- |
| 原生 HLS `maybe` | 浏览器声明可能支持，不证明当前分片可播放 |
| 媒体错误代码 4 | 媒体源无法加载或格式不支持，不能唯一定位到跨域/签名/编码 |
| readyState 0、networkState 3 | 尚未获得可用媒体信息，不等于设备断网 |
| 清单声明 08:57 | 清单内容完整到该时长，不代表所有分片已经访问或解码 |
| errno:71 | 源站错误响应；未核实官方含义，不直接称为“签名过期” |

诊断中的错误 URL 会脱敏。排查应记录设备、Safari/主屏幕入口、版本、媒体实际时长与错误，不公开新的临时签名。

## 排查顺序

1. 确认脚本为 v3.4；旧版本先通过页面更新按钮更新。
2. 确认点击的是默认完整清单或新手动导入记录，而不是历史中的 100 秒记录。
3. 区分清单读取失败和视频播放失败。清单导入报错看表单下方状态；播放失败看“播放诊断”。
4. 分别验证 Safari 与主屏幕 PWA。拖到第 5 分钟并检查画面/声音，不能仅凭时长判成功。
5. 临时分片失效时重新取得完整清单，从原记录的“替换链接”导入；避免反复清空全部站点数据而丢失进度。

当前未实现：自动续签、网盘分享页解析、后端代理、视频离线下载。复制 localStorage 或另开登录标签页不能作为保证完整播放的方案。
